# MAXUP Pricing & Profitability Intelligence

ซอร์สโค้ดระบบราคาโทนแดง Burgundy / Charcoal / Ivory สำหรับ MAXUP พร้อม Backend ที่แยกข้อมูลต้นทุนตามสิทธิ์จริง ไม่ใช้ CSS ซ่อนตัวเลขจากฝ่ายขาย

**สถานะ:** Reference implementation พร้อมรันในเครื่องและทดสอบต่อ ไม่ได้เชื่อมต่อเว็บไซต์หรือฐานข้อมูล MAXUP เดิม ไม่ใช่การรับรองความปลอดภัย 100% หรือระบบบัญชีที่ผ่านการตรวจรับแล้ว

## เริ่มต้นใช้งาน

ต้องมี Python 3.11 ขึ้นไป เปิด Terminal ในโฟลเดอร์นี้ แล้วรัน:

```bash
python -m venv .venv
```

เปิดใช้งาน virtual environment:

```powershell
# Windows PowerShell
.venv\Scripts\Activate.ps1
```

```bash
# macOS / Linux
source .venv/bin/activate
```

ติดตั้งและสร้างบัญชีส่วนบุคคล:

```bash
python -m pip install -r requirements.txt
python app.py user
```

ระบุ email, role เป็น `admin`, `executive` หรือ `sales` และรหัสผ่านอย่างน้อย 12 ตัวอักษร ไม่มีรหัสผ่านกลางหรือบัญชีเริ่มต้นที่ฝังไว้ในโค้ด รันคำสั่งเดิมอีกครั้งเพื่อสร้างบัญชีเพิ่มเติม

หากต้องการทดลองหน้าจอด้วยข้อมูลตัวอย่าง:

```bash
python app.py demo
```

**ทุก SKU ที่ขึ้นต้น DEMO เป็นข้อมูลสาธิต ไม่ใช่ราคาต้นทุน ราคาขาย สต็อก หรือการยืนยันสเปกปัจจุบันของ MAXUP** ค่า Market Reference เว้นว่าง ไม่มีการเดาราคาตลาด

เปิดระบบ:

```bash
python app.py run
```

เข้า `http://127.0.0.1:8000` และลงชื่อเข้าด้วยบัญชีที่สร้างไว้ คำสั่ง run เป็นเซิร์ฟเวอร์พัฒนาสำหรับเครื่องตนเอง หากไม่ได้ตั้ง secret ถาวร การรีสตาร์ตจะทำให้ต้องเข้าสู่ระบบใหม่

## กฎธุรกิจและสูตร

- เงินในฐานข้อมูลเก็บเป็นจำนวนเต็มหน่วยสตางค์ ใช้ Decimal แปลงเงินและคำนวณต้นทุนนำเข้า ปัด HALF_UP ที่ 2 ตำแหน่ง
- PO Cost หมายถึงราคาต่อคันในสกุลเงินต้นทาง ต้องอ้างอิงเอกสารโรงงานจริง
- Estimated (THB/คัน) = PO × FX ของลอต × Landed Cost Factor เช่น 1.15 หมายถึงเพิ่ม 15% ไม่ใช่บวก 1.15 บาท
- ใช้ factor ที่ระบุรายลอต ในชุดนี้ยังไม่มีหน้าตั้งค่า default factor แยกตามหมวด
- Actual เป็นต้นทุนรวมการนำเข้าต่อคันใน THB ที่ผู้บริหารบันทึกหลังตรวจเอกสาร ไม่ใช่ยอดทั้ง shipment
- กำไรขั้นต้น = ราคาขายก่อน VAT − ต้นทุนสินค้า
- Markup = กำไรขั้นต้น / ต้นทุน × 100 เมื่อทุนเป็นศูนย์แสดง —
- Gross Margin = กำไรขั้นต้น / ราคาขาย × 100 เมื่อราคาขายเป็นศูนย์แสดง —
- ตัวอย่างทุน 100,000 ขาย 120,000: กำไรขั้นต้น 20,000 / MU 20.00% / GM 16.67%
- เตือน GM ต่ำกว่า 15% ในตารางและ Dashboard เกณฑ์นี้ยังไม่ได้ทำหน้าตั้งค่า
- ราคาแพ็กจำนวนมาก = max(Floor Price, ราคาใน tier ที่เลือก × (1 − ส่วนลด/100)) ปัดแสดง 2 ตำแหน่ง Floor Price ต้องไม่สูงกว่าราคาใดใน 4 tiers
- ไม่มีการอ้างว่าตัวเลขนี้คือกำไรสุทธิ เพราะยังไม่รวมค่าใช้จ่ายดำเนินงาน ดอกเบี้ย และภาษีเงินได้
- Dashboard โครงสร้างราคาใช้ต้นทุนลอตที่บันทึกล่าสุดของสินค้านั้น พร้อมระบุ Actual/Estimated ไม่ใช่ Weighted Average และไม่ใช่ realized profit
- มูลค่าสต็อกต้นทุนจริง = ผลรวมจำนวนคงเหลือแต่ละลอต × Actual ของลอตนั้น ลอตที่ยังไม่ทราบ Actual แสดงในบล็อกประมาณการแยกต่างหาก
- รับรู้กำไรจริงได้เฉพาะการขายลอตที่มี Actual บันทึกต้นทุนของลอตไว้ในแถวขายเพื่อรักษาฐานกำไรย้อนหลัง
- Invoice + lot เดิมบันทึกได้ครั้งเดียว หากมีสินค้าจากลอตเดียวกันหลายแถวในเอกสาร ให้รวมจำนวนก่อนบันทึก
- ไม่อนุญาตเปลี่ยน Actual หลังลอตมีการขายแล้ว กระบวนการ cost adjustment ทางบัญชียังต้องพัฒนาเพิ่ม
- การอนุมัติพิเศษมีผลต่อคำขอเฉพาะรายการ ไม่เปลี่ยน Floor Price กลาง และยังไม่ใช่ใบเสนอราคาหรือคำสั่งขายอัตโนมัติ
- ตลาดอ้างอิงกรอกเองเท่านั้น ไม่ดึงราคาภายนอกโดยอัตโนมัติ

## การนำเข้าและประวัติราคา

1. Admin ดาวน์โหลด Template จากเมนูนำเข้า Excel
2. หนึ่งแถวต่อหนึ่ง SKU กรอกชื่อ หมวด สเปก ราคา วันมีผล และเปอร์เซ็นต์ส่วนลด
3. ต้องใช้หัวตารางตรงกับ Template ไม่รองรับสูตร ให้แปลงเป็นค่าก่อนอัปโหลด
4. Preview ตรวจทุกรายการ ค่าเดิม → ใหม่ ไฟล์นี้ไม่รองรับนำเข้าต้นทุน เพื่อแยกกระบวนการจากเอกสาร PO
5. ระบุเหตุผลแล้วกด Confirm เท่านั้นจึงบันทึกและสำรองฐานข้อมูล
6. SKU ที่ไม่อยู่ในไฟล์จะไม่ถูกลบ Unchanged จะไม่ถูกเขียนใหม่
7. หากมีการแก้สินค้าหรือราคาหลัง Preview ระบบปฏิเสธ Confirm เพื่อให้อัปโหลดตรวจใหม่ Preview หมดอายุ 30 นาที

ประวัติมีผลระดับวันตาม Asia/Bangkok ราคาวันเดียวกันใช้เวอร์ชันที่บันทึกหลังสุด การดูอดีตเลือกเวอร์ชันตาม effective date ไม่ใช่เวลาที่ระบบเคยทราบข้อมูล (ยังไม่ใช่ bitemporal accounting) **ชื่อและสเปกสินค้าใช้ค่าปัจจุบัน** หากต้องการหลักฐานใบเสนอราคาเดิมต้องเพิ่ม snapshot ใบเสนอราคาแยก ไม่ควรใช้ประวัติราคาแทนเอกสารใบเสนอราคาที่ออกแล้ว

## สำรองและกู้คืน

ข้อมูลอยู่ใน `instance/maxup.sqlite3` นอกโฟลเดอร์ static และไม่ได้แนบในชุดซอร์สโค้ด

Rollback เป็นกระบวนการดูแลเซิร์ฟเวอร์แบบ offline ยังไม่มีปุ่มใน UI:

1. ปิดบริการและหยุดผู้ใช้งานทั้งหมดก่อน
2. สำรองฐานข้อมูลปัจจุบันไว้อีกชุด โดยใช้ SQLite backup API หรือเครื่องมือ SQLite
3. เลือกไฟล์ `instance/backups/*.sqlite3` ที่ต้องการ ตรวจสอบด้วย `PRAGMA integrity_check;`
4. กู้คืนไฟล์สำรองแทนฐานข้อมูลปัจจุบัน ให้แน่ใจว่าไม่มี connection/WAL ค้างอยู่ ใช้ผู้ดูแลที่เข้าใจกระบวนการ SQLite
5. เปิดบริการและตรวจบัญชี ราคา สต็อก และยอดขาย

**การกู้คืนฐานข้อมูลทั้งชุดจะย้อนรายการทั้งหมดหลังเวลา backup ไม่ใช่ย้อนเฉพาะราคา** ควรยืนยันรายการที่จะได้รับผลกระทบก่อนทำจริง สำรองในเซิร์ฟเวอร์เดียวกันไม่แทน offsite backup

## Production deployment

ชุดนี้ใช้ Python/Flask + SQLite + Vanilla JS ไม่ใช่ไฟล์ที่นำไปแทน Cloudflare Worker ได้โดยตรง หากเว็บไซต์เดิมใช้ stack อื่น ให้ย้าย business rules และ API contracts ไปใช้กับ stack เดิม แทนการแทนที่ระบบทันที

ตัวอย่าง Linux server หลัง reverse proxy ที่ตั้งค่า HTTPS แล้ว:

```bash
export MAXUP_SECRET_KEY="$(python -c 'import secrets; print(secrets.token_hex(32))')"
export MAXUP_HTTPS=1
export MAXUP_DATA_DIR=/absolute/private/persistent/maxup-data
# สร้างบัญชีใน DATA_DIR เดียวกันก่อนเริ่มบริการ
python app.py user
gunicorn --workers 2 --bind 127.0.0.1:8000 wsgi:app
```

เก็บ secret ใน secret manager หรือ environment ของ hosting ให้คงที่ทุก process/restart ไม่ฝังใน source control ไฟล์ `.env.example` เป็นตัวอย่างชื่อค่าและไม่ถูกโหลดอัตโนมัติ บังคับ HTTPS และเก็บ SQLite ใน persistent local disk ที่มี permission เฉพาะ service user ไม่ใช่ webroot หรือ network filesystem

ก่อนเปิดใช้กับข้อมูลจริง ยังต้องตรวจรับด้านสิทธิ์ การตั้งค่าโฮสต์ การกู้คืน ภาระผู้ใช้ และการเชื่อมต่อข้อมูลเดิม ไม่มีซอฟต์แวร์ที่รับรองปลอดภัย 100% ในทุกเงื่อนไข

### ขอบเขตที่ต้องพัฒนาต่อก่อนใช้เป็นระบบองค์กรเต็มรูปแบบ

- SSO, MFA, reset password, invite user, หน้าจัดการบัญชี/ถอนสิทธิ์ (ตอนนี้สร้างบัญชีด้วย CLI)
- การเชื่อมต่อ Sales Order/Invoice หรือการ Import ยอดขายเป็นชุด ปัจจุบันบันทึกยอดขายผ่านหน้า UI/API ทีละรายการ
- บัญชีคืนสินค้า ยกเลิก Invoice ส่วนลดท้ายบิล ค่าใช้จ่ายดำเนินงาน การปันส่วนภาษี/ค่าขนส่งและ cost adjustment ย้อนหลัง
- การเชื่อมต่อภายนอกต้องเพิ่ม idempotency key ระดับระบบต้นทาง ปัจจุบันมี unique constraint ต่อ Invoice + lot ป้องกันบันทึกแถวเดิมซ้ำ โดยหนึ่ง Invoice ให้รวมจำนวนของลอตเดียวกันเป็นแถวเดียว และยังไม่มีระบบแก้/ยกเลิกเอกสารขาย
- การบันทึก audit ของการ login ล้มเหลว การเปลี่ยนสิทธิ์ และการส่งออกข้อมูล
- Immutable history ระดับสิทธิ์ database user/ระบบจัดเก็บที่แก้ย้อนหลังไม่ได้ SQLite trigger ป้องกันผ่านแอปนี้ แต่ผู้ดูแลเครื่องที่เข้าถึงไฟล์ฐานข้อมูลยังสามารถแก้หรือถอด trigger ได้
- สิทธิ์ระดับ database เช่น PostgreSQL RLS (ชุดนี้ enforce role/field projection ที่ backend ไม่ใช่ DB-native RLS)
- Default factor แยกหมวด, dashboard drill-down แบบคลิกหมวด, หน้าตั้งค่า margin guardrail
- Backup encryption, offsite retention, automated recovery test และปุ่ม Rollback ที่กำหนดขอบเขตชัดเจน
- Historical quote snapshots พร้อมเงื่อนไขลูกค้าและราคาเก่าตอนออกเอกสารจริง
- การทดสอบ UI ด้วยเบราว์เซอร์จริงและการตรวจ accessibility ขั้นสมบูรณ์ ยังไม่ได้ทำในสภาพแวดล้อมนี้

## การทดสอบ

```bash
python -m pytest -q
node --check static/app.js
```

Integration tests ใช้ฐานข้อมูลชั่วคราว แยกจากข้อมูลใช้งาน ทดสอบการไม่ส่งต้นทุนให้ฝ่ายขาย สิทธิ์ API CSRF วันมีผลย้อนหลัง/อนาคต immutability trigger สำรอง Import ยืนยันซ้ำ Preview ล้าสมัย สต็อกไม่พอ และ realized profit จาก Actual

ไฟล์หลัก: `app.py` backend / `templates/index.html` โครง UI / `static/style.css` ธีมและ responsive / `static/app.js` การทำงานหน้าเว็บ / `test_app.py` integration tests / `wsgi.py` production entrypoint
